# GitHub에서 관리하고 Cloudflare Pages에 정적 PWA 배포

앱은 React, TypeScript 및 Vite로 빌드하는 서버 없는 정적 PWA로 구성한다. 소스와 변경 이력은 GitHub 저장소에서 관리하고 Cloudflare Pages가 저장소와 연결되어 빌드, 미리보기 및 운영 배포를 수행한다. 서버 렌더링, API 프록시 및 데이터베이스를 두지 않으며 사용자 브라우저가 넥슨 API를 직접 호출한다.

이 구성은 사용자 API 키가 애플리케이션 서버를 통과하지 않는 경계를 명확히 하고 정적 호스팅 비용과 운영 부담을 줄인다. Cloudflare의 응답 헤더 설정으로 강한 Content Security Policy를 적용한다. 대신 기기 간 데이터 동기화와 서버 기반 기능은 제공하지 않으며, 넥슨 API의 브라우저 CORS 정책이 변경되면 서비스 동작이 제한될 수 있다.

PWA 설치는 선택 사항이다. 모든 핵심 기능은 일반 웹사이트에서 제공하며, 캐릭터 선택과 첫 동기화 이후 설정 화면에서만 `홈 화면에 추가` 기능을 제공한다. 자동 설치 팝업이나 반복 권유는 표시하지 않는다.

패키지 관리는 npm과 `package-lock.json`으로 통일하고 지원되는 Node.js LTS 버전을 저장소에서 고정한다. 초기 배포는 Cloudflare의 `pages.dev` 주소를 사용하며 서비스가 안정된 뒤 별도 도메인을 연결한다.

런타임 의존성은 React, React DOM, Zod 및 idb를 기본 상한으로 삼는다. 라우팅 라이브러리, 전역 상태 관리 라이브러리, UI 프레임워크, 외부 아이콘 CDN, 분석 도구는 도입하지 않는다. 테스트와 빌드에는 Vite, TypeScript, Vitest, Testing Library, Playwright 및 ESLint를 사용한다. 새 의존성은 직접 구현할 때의 오류 위험이나 유지보수 비용이 더 크다는 근거가 있을 때만 추가한다. 이는 평문 API 키에 접근할 수 있는 번들 코드와 공급망 공격 표면을 줄이고 공개 저장소에서의 검토를 단순하게 한다.

MVP는 자동 오류 수집이나 `진단 정보 복사` 기능을 제공하지 않는다. 복구 가능한 오류에는 한국어 설명, 짧은 오류 코드와 다시 시도 동작을 제공하고 설정 또는 하단에서 GitHub Issues로 이동할 수 있게 한다. 실제 운영에서 지원에 필요한 정보가 부족하다는 근거가 생길 때만 개인정보와 API 키를 제외한 진단 내보내기를 별도로 검토한다.
